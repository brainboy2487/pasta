

# Phase 11 — **Module System**  
**Goal:** Make Pasta capable of organizing code at scale.

### Deliverables
- `import` / `export` syntax finalized  
- Module resolution rules (relative, absolute, package-based)  
- Compiler support for module graphs  
- Circular dependency detection  
- Namespaces + symbol visibility rules  

### Why this phase matters  
Everything after this — packages, stdlib, tooling — depends on a stable module system.

---

# Phase 12 — **Error & Result Model**  
**Goal:** Define how Pasta handles failure.

### Deliverables
- Decide between exceptions, `Result<T,E>`, or hybrid  
- Panic semantics  
- Stack unwinding rules  
- Error propagation syntax  
- Standard error types  

### Why this phase matters  
You need this before a standard library or package ecosystem can exist.

---

# Phase 13 — **Memory Model**  
**Goal:** Lock down how objects live and die.

### Deliverables
- Choose: ARC, tracing GC, manual, or hybrid  
- Define ownership semantics  
- Define mutability rules  
- Runtime allocator integration  
- Compiler hooks for memory ops  

### Why this phase matters  
This determines performance, safety, and FFI behavior.

---

# Phase 14 — **Traits / Interfaces**  
**Goal:** Introduce polymorphism beyond inheritance.

### Deliverables
- Trait definition syntax  
- Trait implementation syntax

- Static dispatch rules  
- Trait objects (if applicable)  

### Why this phase matters  
Traits unlock generics, collections, and expressive APIs.

# Phase 15 — **Generics**  
**Goal:** Make Pasta capable of writing reusable, type-safe abstractions.
